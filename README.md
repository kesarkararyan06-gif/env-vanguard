> **Zero-dependency environment variable validator.** Validates `process.env` against a schema at startup, collects *all* errors before throwing, and can generate a `.env.example` from the schema.

---

## Why env-vanguard?

| Pain | Without env-vanguard | With env-vanguard |
|------|----------------------|--------------------|
| Missing variable | Cryptic runtime crash deep in your app | Clear error at startup: `"DATABASE_URL" is required but was not provided.` |
| Wrong type | `"true"` treated as truthy string instead of boolean | Coerced to real `boolean` |
| Multiple bad vars | Fix one, restart, discover the next one | All errors listed at once |
| Onboarding | No single source of truth for required vars | Auto-generated `.env.example` |

**What it does not do:** load `.env` files (use [`dotenv`](https://github.com/motdotla/dotenv) first), TypeScript inference, async loading, or remote config fetching.

## Quick Start

```js
// CommonJS
const { validate } = require('env-vanguard');

// ESM
import { validate } from 'env-vanguard';
```

Call `validate()` **at the very top of your entry point**, before anything else:

```js
const { validate } = require('env-vanguard');

const env = validate({
  PORT:        { type: 'number',  required: false, default: 3000 },
  NODE_ENV:    { type: 'enum',    values: ['development', 'production', 'test'] },
  DATABASE_URL:{ type: 'string',  description: 'PostgreSQL connection URL' },
  DEBUG:       { type: 'boolean', required: false, default: false },
});

// All values are coerced — env.PORT is a number, env.DEBUG is a boolean
console.log(`Starting on port ${env.PORT} in ${env.NODE_ENV} mode`);
```

If anything is wrong, you get **one clear message listing every problem**:

```
EnvValidationError: Environment validation failed with 2 error(s):
  1. "DATABASE_URL" is required but was not provided.
  2. "NODE_ENV" must be one of ["development", "production", "test"], got "prod".
```

## API Reference

### `validate(schema, options?)`

Validates environment variables and returns a **frozen** object of coerced values.

**Parameters**

| Parameter | Type | Description |
|-----------|------|-------------|
| `schema` | `Schema` | Object mapping variable names to `FieldSpec` definitions. |
| `options.env` | `Object` | Environment to validate. Defaults to `process.env`. |
| `options.strict` | `boolean` | When `true`, any variable in `env` not declared in `schema` causes an error. Default: `false`. |

**Returns:** `Readonly<Record<string, string | number | boolean>>`

**Throws:**
- `SchemaError` — if the schema definition is malformed (bad type, missing `values` for enum, wrong default type, etc.). Thrown immediately without collecting.
- `EnvValidationError` — if one or more variables fail validation. Contains `.errors: string[]` with every individual message.

---

### `generateExample(schema)`

Generates `.env.example` file content from a schema.

**Parameters**

| Parameter | Type | Description |
|-----------|------|-------------|
| `schema` | `Schema` | Same schema object used for `validate()`. |

**Returns:** `string` — The content to write to `.env.example`.

**Throws:** `SchemaError` — if the schema is malformed.

**Example:**

```js
const { generateExample } = require('env-vanguard');
const fs = require('fs');

const schema = {
  DATABASE_URL: { type: 'string', description: 'PostgreSQL connection string', example: 'postgres://user:pass@localhost/db' },
  PORT:         { type: 'number', required: false, default: 3000, description: 'HTTP port' },
};

fs.writeFileSync('.env.example', generateExample(schema));
```

Output:

```dotenv
# .env.example — generated by env-vanguard

# PostgreSQL connection string
# Type: string | Required
DATABASE_URL=postgres://user:pass@localhost/db

# HTTP port
# Type: number | Optional | Default: 3000
PORT=3000
```

---

### `FieldSpec`

Each key in `schema` maps to a `FieldSpec` object:

| Property | Type | Default | Description |
|----------|------|---------|-------------|
| `type` | `'string' \| 'number' \| 'boolean' \| 'enum'` | `'string'` | Expected type. |
| `required` | `boolean` | `true` | If `false`, the variable is optional. |
| `default` | `string \| number \| boolean` | — | Used when the variable is absent. Only for optional fields. |
| `values` | `string[]` | — | **Required** when `type` is `'enum'`. List of allowed values. |
| `description` | `string` | — | Shown in `.env.example` comments. |
| `example` | `string \| number \| boolean` | — | Shown as the value in `.env.example` (overrides `default`). |

---

### Type coercion rules

| Type | Raw string input | Coerced value |
|------|-----------------|---------------|
| `string` | `"hello"` | `"hello"` |
| `number` | `"3000"` | `3000` |
| `boolean` | `"true"` or `"1"` | `true` |
| `boolean` | `"false"` or `"0"` | `false` |
| `enum` | `"production"` | `"production"` |

**Empty string** (`VAR=`) is treated as absent — the default is used, or an error is raised if `required`.

---

### Error Classes

#### `EnvValidationError`

```js
const { EnvValidationError } = require('env-vanguard');

try {
  validate(schema);
} catch (err) {
  if (err instanceof EnvValidationError) {
    console.error('Config errors:', err.errors); // string[]
  }
}
```

| Property | Type | Description |
|----------|------|-------------|
| `name` | `'EnvValidationError'` | Error name. |
| `message` | `string` | Full aggregated message. |
| `errors` | `string[]` | Individual validation error messages. |

#### `SchemaError`

Thrown when the schema itself is invalid (wrong type name, missing enum values, etc.).

| Property | Type | Description |
|----------|------|-------------|
| `name` | `'SchemaError'` | Error name. |
| `message` | `string` | Description of the schema problem. |

## Examples

### Basic server config

```js
const { validate } = require('env-vanguard');

const env = validate({
  PORT:     { type: 'number',  required: false, default: 3000 },
  HOST:     { type: 'string',  required: false, default: 'localhost' },
  NODE_ENV: { type: 'enum',    values: ['development', 'production', 'test'], required: false, default: 'development' },
  LOG_LEVEL:{ type: 'enum',    values: ['debug', 'info', 'warn', 'error'], required: false, default: 'info' },
});
```

### Catch and display all errors

```js
const { validate, EnvValidationError } = require('env-vanguard');

try {
  validate(schema);
} catch (err) {
  if (err instanceof EnvValidationError) {
    process.stderr.write(`\n❌ Bad configuration:\n`);
    err.errors.forEach((msg) => process.stderr.write(`  • ${msg}\n`));
    process.stderr.write('\n');
    process.exit(1);
  }
  throw err;
}
```

### Strict mode (no undeclared vars)

```js
validate(schema, { strict: true });
// throws if process.env has any key not declared in schema
```

### Generate .env.example in a build script

```js
const { generateExample } = require('env-vanguard');
const fs = require('fs');
const schema = require('./src/schema'); // shared schema module

fs.writeFileSync('.env.example', generateExample(schema));
console.log('Generated .env.example');
```

## Limitations

- Does not load `.env` files. Use [`dotenv`](https://github.com/motdotla/dotenv) before calling `validate()`.
- Enum values must be strings. If you need numeric enums, validate as `'number'` and check in your own code.
- No async schema (e.g., fetching allowed values from a remote source).
- No nested objects — environment variables are always flat strings.
